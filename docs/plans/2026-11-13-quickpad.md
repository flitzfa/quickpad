# QuickPad Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Editor de texto residente en la bandeja que abre una ventana de vidrio junto al archivo seleccionado en el Explorador con doble Ctrl, para ver, editar, buscar y guardar en segundos.

**Architecture:** Un solo proceso WPF que queda en la bandeja. Un hook de teclado global le pasa eventos a un detector puro de doble toque. El lector del Explorador (COM + UI Automation) devuelve el archivo seleccionado y su posición en pantalla. Una única `GlassWindow` reutilizada lo muestra. La lógica pura (detector, archivo, formato de vista previa, búsqueda) vive en clases sin Win32 y tiene tests xUnit. Lo que toca Win32 o la interfaz se verifica a mano.

**Tech Stack:** C# 14, .NET 10 (LTS), WPF + `NotifyIcon` de WinForms, xUnit.

**Spec:** `docs/specs/2026-11-13-quickpad-design.md`

## Global Constraints

- `TargetFramework` = `net10.0-windows`; `<Nullable>enable</Nullable>`; `<ImplicitUsings>enable</ImplicitUsings>`; `<UseWPF>true</UseWPF>`.
- Sin paquetes NuGet en la app. P/Invoke escrito a mano con `[LibraryImport]` en `src/QuickPad/Interop/Native.cs`. En los tests, solo xUnit y su runner.
- Solo Windows 11.
- Doble Ctrl: menos de **350 ms** entre toques, sin otra tecla en el medio y solo con ventana activa `CabinetWClass`.
- Vista previa: primeras **40 líneas**, lectura de los primeros **64 KB** como máximo.
- Edición: más de **5 MB** pide confirmación.
- Objetivos: ventana visible en **< 150 ms**, **~20 MB** de RAM en la bandeja y **< 60 MB** con la ventana visible.
- Log en `%LOCALAPPDATA%\QuickPad\log.txt`.
- Textos de la interfaz en español rioplatense, tal como figuran en el spec ("Este archivo no es texto", "Guardar / Descartar / Seguir editando", "El archivo cambió afuera. Sobrescribir / Recargar").

## Review Focus

1. **Doble Ctrl mientras se renombra un archivo en el Explorador:** se espera que no abra nada. Lo cubre el chequeo de foco en la Task 5.
2. **Archivo vacío (0 bytes):** se abre como texto UTF-8 vacío, no como binario. Lo cubre `Open_EmptyFile_IsEmptyUtf8` en la Task 2.
3. **Archivo borrado o movido entre abrirlo y guardarlo:** se trata como cambio externo y "Sobrescribir" lo recrea. Lo cubre `Save_DeletedFile_ThrowsChangedExternally` en la Task 3.
4. **Línea gigante (JSON minificado) en la vista previa:** cada línea se corta a 200 caracteres con "…". Lo cubre `Format_LongLine_IsTruncated` en la Task 4.
5. **Doble Ctrl con la ventana ya abierta:** si es el mismo archivo, se cierra (toggle). Si es otro, lo cambia, preguntando antes si hay cambios sin guardar. Lo cubre el paso manual de la Task 9.

> **Desvío declarado respecto del spec:** el color de las claves y el tapado de secretos se aplican solo en vista previa, que es un `TextBlock` con `Run`s. El modo edición usa un `TextBox` sin colores. Colorear un `TextBox` exige un `RichTextBox`, que es lento y pesado y va contra el objetivo de RAM.

### Task 2: TextFile — abrir y detectar

**Files:**

**Interfaces:**
- Produces:
  - `public enum LineEnding { CrLf, Lf }`
  - `public sealed record TextDocument(string Path, string Text, Encoding Encoding, LineEnding LineEnding, DateTime LastWriteUtc, long Length, bool Truncated)`
  - `public sealed class NotTextException(string path) : Exception`
  - `public static class TextFile` con:
    - `public const int PreviewBytes = 64 * 1024`
    - `public const long EditSizeLimit = 5L * 1024 * 1024`
    - `public static bool IsBinary(ReadOnlySpan<byte> head)`: hay `0x00` en los primeros 8 KB y no hay BOM UTF-16.
    - `public static TextDocument Open(string path, int maxBytes = int.MaxValue)`: lanza `NotTextException`.

Detalles:
- Codificación: si hay BOM (UTF-8 / UTF-16 LE / UTF-16 BE), se usa ese. Si no, se prueba `new UTF8Encoding(false, true)` y, si tira `DecoderFallbackException`, se usa `Encoding.GetEncoding(CultureInfo.CurrentCulture.TextInfo.ANSICodePage)`. Esto requiere `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` una vez, en un constructor estático. UTF-8 con BOM queda como `new UTF8Encoding(true)` y sin BOM como `new UTF8Encoding(false)`, así `Save` preserva el BOM.
- `LineEnding`: `CrLf` si hay al menos tantos `\r\n` como `\n` sueltos; si no, `Lf`. Un archivo sin saltos de línea queda como `CrLf`.
- Si se leyó con `maxBytes` y faltó contenido, `Truncated = true`. Al truncar, se descarta un posible carácter multibyte cortado al final.

  - `public static TextDocument Save(TextDocument doc, string newText, bool force = false)`: devuelve el documento actualizado, con la nueva `LastWriteUtc` y el nuevo `Length`.

Pasos de `Save`:
1. Si `!force`, verifica que el archivo exista y que su `LastWriteTimeUtc` y su `Length` coincidan con los de `doc`. Si no, lanza `FileChangedExternallyException`.
2. Normaliza todos los saltos de línea de `newText` con `Regex.Replace(newText, "\r\n|\r|\n", eol)`.
3. Escribe preámbulo + bytes en `"{path}.quickpad.tmp"`.
4. Reemplaza el original con `File.Replace(tmp, path, null)` si el archivo existe, o con `File.Move(tmp, path)` si no.
5. Si algo falla, borra el temporal en el `finally` y vuelve a lanzar la excepción. Las `UnauthorizedAccessException` (solo lectura) suben tal cual.

Funcionamiento:
- `SetWindowsHookEx(WH_KEYBOARD_LL)`. El delegado se guarda en un campo para que el GC no lo recolecte.
- En el callback:
  1. Si la ventana activa (`GetForegroundWindow` + `GetClassName`) no es `CabinetWClass`, llama a `detector.Reset()` y sigue de largo.

  3. Si el detector dispara, consulta `GetGUIThreadInfo`. Si el foco está en una ventana de clase `Edit` (renombrando), no hace nada. Si no, ejecuta `Dispatcher.BeginInvoke(DoubleCtrl, hwnd)`.
- El callback **siempre** retorna `CallNextHookEx` y no hace trabajo pesado.
